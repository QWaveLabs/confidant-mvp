# Local run reporting, additive MVP scope

User-approved addition on 2026-09-30. This small local HTML report extends ticket 22 operational health and ticket 24 verification; it supersedes the original spec's exclusion of an HTML guide/dashboard only for this private run-results view. Chat and the install skill remain the guided interface. No hosted dashboard, account connection, cadence change, message send, vault or deployment is authorized by this addition.

Use structured persistent records as the source of truth. Each task has a stable ID; each run records IDs, mode, start/end/update times, outcome, bounded approved summaries, errors, coverage and archive path. Keep queued/running status distinct from terminal completed/partial/failed/skipped. Retain prior section results when omitted, clear only explicit empty sections, and retain source snapshots independently of unrelated task results. Do not infer the next schedule or source coverage from process success.

Render one stable self-contained latest.html and timestamped archive per run with a fixed responsive design. Include attention/approvals/blockers, three priorities, commitments, findings/changes/completions, recommendations, drafts, actual actions, task outcomes, verified schedule information, freshness/coverage and history links. Escape content, validate approved links and reject raw archives, excluded text and common credentials. Show each result/section's update time. No external assets or tracking.

Use exclusive bounded cross-process locking, immutable run identity/order, private files, fsync/atomic rename and safe aggregation. A later completion of an older overlapping run cannot replace a newer result. Failed/skipped and refused private input produce safe reports when possible. Saving/opening claims require successful receipts. Purge owned history on registered privacy tightening/deletion and revoke pending runs.

Opening is configurable independently of tasks. Attempt after save only in a verified unlocked online usable session. Prefer supported default-browser tab reuse with one stable URL and a cooldown. Never wake/unlock/launch a missing session. Record skipped/failed/unknown accurately. Browser inspection is required before visual acceptance; if blocked, preserve that gap instead of fabricating it.

Implementation: src/reporting.mjs, src/report-template.mjs, src/report-cli.mjs, src/browser.mjs, and chat reporting tools. Evidence: docs/evidence/local-reporting-result.md. Automated acceptance covers all outcomes, two overlapping processes, retained sections/source snapshots, own-run archives, escaping, links, long content, exact date-only deadlines, purge and browser mocks. Actual visual acceptance remains unverified because the browser tool blocked local-file access under its security policy.
